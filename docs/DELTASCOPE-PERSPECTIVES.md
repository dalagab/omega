# DeltaScope perspectives

The perspective switch behaves like an application/workbench switch, not a cosmetic density setting. All perspectives read the same evidence, but each has a different default workflow and navigation.

## Plugin Developer

Goal: understand what Omega found on **my plugin** and improve explanations/indexing.

Primary tasks: Security Review, Journey, Changes, Omega Profile, Source & Build.

## Investigator

Goal: follow a specific case/plugin from finding to evidence.

Primary tasks: Cases, Journey, Findings, Events, Relationships, Intelligence, Published Evidence.

## Security Researcher

Goal: study the ecosystem and develop/replay deterministic detections.

Primary tasks: Plugins, Findings, Intelligence, Relationships, Rules, Compare, Reports, Data.

## Operations

Goal: verify that collectors, analysis pipelines, queues and authority boundaries are healthy.

Primary tasks: Overview, Pipelines, Collectors, Scan Queue, Evidence, Definitions & Gates, Reports.

The perspective changes the information architecture and default actions; it does not alter or filter the underlying security evidence.
