= Interdimensional Rift: Dynamic Observation and Sandbox Hardening Plan
:toc:
:toclevels: 3
:sectnums:

== Purpose

Interdimensional Rift is the dynamic-observation companion to SigmaScope.
SigmaScope remains deterministic and static: it MUST NOT load or execute plugin
code. Rift is allowed to execute a plugin only inside a disposable, externally
supervised Linux sandbox and records what that exact artifact attempts while a
small set of deterministic Dalamud lifecycle scenarios are exercised.

Rift is not a malware verdict engine and MUST NOT assign risk or severity merely
because an API was touched. Its output is evidence. SigmaScope/SRL/Definition
Packs may later correlate that evidence with static observations and project it
into user-facing explanations.

The target relationship is:

[source,text]
----
installable artifact
   |-- SigmaScope --> static observations -------------------+
   |-- Rift -------> runtime observations -------------------+--> SRL/correlation --> Omega evidence
   `-- YARA/AV/OSV -> specialist security-hygiene evidence --+
----

== Non-negotiable security invariants

. SigmaScope never imports, loads, reflects over as executable code, or invokes a
  plugin assembly.
. Rift receives only the installable artifact being examined plus its own frozen
  runtime. It never receives the repository checkout, runner home, SSH material,
  GitHub token, Docker socket, catalog publication credentials, or signing keys.
. Rift has no route to the public Internet or the runner LAN.
. A plugin run occurs in a fresh process tree and a fresh Bubblewrap sandbox.
. Failure to establish the sandbox is terminal. There is no unsandboxed fallback.
. The hard timeout is enforced by an external supervisor that can kill the whole
  Bubblewrap process tree; a `Task.Wait()` timeout inside .NET is not a security
  boundary.
. The plugin artifact is mounted read-only.
. Writable state exists only on bounded tmpfs mounts and disappears when the run
  finishes.
. Host environment variables are cleared and a tiny allow-list is rebuilt.
. Bubblewrap must be a modern non-setuid build and must not have file
  capabilities.
. Nested user namespace creation is disabled inside the prisoner.
. Runtime evidence always identifies the exact artifact SHA-256 and the sandbox
  environment/scenario revision.

== Threat model

Rift must assume the plugin is deliberately hostile. Expected hostile behaviour
includes:

* arbitrary managed code in a constructor, static constructor, lifecycle method,
  callback, finalizer, or worker thread;
* direct `HttpClient`, sockets, DNS, files, registry-like APIs, native libraries,
  process creation, reflection, dynamic assembly loads, and P/Invoke;
* infinite loops, thread/fork bombs, memory exhaustion, disk filling and hangs;
* attempts to inspect environment variables, home directories, process state,
  source workspaces and credentials;
* attempts to outlive the scan after the logical Dalamud lifecycle ends.

Rift does not claim that Bubblewrap alone provides VM-grade isolation from Linux
kernel vulnerabilities. GitHub-hosted jobs add a disposable VM boundary around
this mechanism. A later executor may use a microVM for artifacts requiring a
stronger isolation class without changing Rift's observation schema.

== GitHub runner preparation

Ubuntu 24.04 mediates unprivileged user namespaces with AppArmor. Bubblewrap's
own GitHub Actions CI enables user namespaces on the disposable runner before
its smoke tests. Rift follows the same pattern and verifies the actual boundary
before any untrusted artifact is staged.

The repository now contains:

[source,text]
----
tools/enable-userns-github.sh
tools/verify-bwrap.sh
----

The setup MUST fail closed. Do not write `|| true` around namespace setup or the
boundary probe.

A representative setup is:

[source,yaml]
----
- name: Install Bubblewrap
  run: |
    sudo apt-get update
    sudo apt-get install -y --no-install-recommends bubblewrap libcap2-bin

- name: Enable user namespaces on disposable runner
  run: sudo ./tools/enable-userns-github.sh

- name: Verify Rift boundary
  run: ./tools/verify-bwrap.sh
----

== Bubblewrap executor

`tools/run-rift-bwrap.sh` is the first hardening implementation. It requires a
self-contained `linux-x64` Rift publication so `/usr/bin`, the user's home and
the GitHub workspace do not need to be mounted into the jail.

Representative invocation:

[source,bash]
----
./tools/build-rift-seccomp.sh ./artifacts/rift-seccomp.bpf
./tools/run-rift-bwrap.sh \
  --runtime-dir ./artifacts/rift-linux-x64 \
  --artifact-dir ./staging/SomePlugin \
  --plugin ./staging/SomePlugin/SomePlugin.dll \
  --seccomp-policy ./artifacts/rift-seccomp.bpf \
  --out ./results/rift.json \
  --init-timeout 10 \
  --wall-timeout 20
----

The important options are equivalent to:

[source,bash]
----
bwrap \
  --unshare-user \
  --unshare-ipc \
  --unshare-pid \
  --unshare-net \
  --unshare-uts \
  --unshare-cgroup-try \
  --disable-userns \
  --new-session \
  --die-with-parent \
  --cap-drop ALL \
  --clearenv \
  --ro-bind "$RIFT_RUNTIME" /rift \
  --ro-bind "$ARTIFACT_DIR" /input \
  --proc /proc \
  --dev /dev \
  --size 134217728 --tmpfs /tmp \
  --size 16777216  --tmpfs /home \
  --size 33554432  --tmpfs /work \
  ... \
  /rift/interdimensional-rift /input/plugin.dll
----

Pass 2 moves the hard wall/resource boundary into a transient systemd service.
`MemoryMax`, `MemorySwapMax`, `TasksMax`, `CPUQuota`, `RuntimeMaxSec` and
`KillMode=control-group` apply to the complete Bubblewrap descendant tree. An
inner GNU `timeout --kill-after` produces an explicit timeout marker/report; the
cgroup remains authoritative if a descendant tries to outlive that wrapper.

== Resource limits

Bubblewrap is primarily a namespace/filesystem sandbox. Resource accounting is a
separate control.

Pass 2 implements cgroup-v2 limits around every production invocation using a
transient systemd service on GitHub-hosted Ubuntu. There is deliberately no
portable unsandboxed/resource-unbounded production fallback: if the cgroup
boundary cannot be created, Rift refuses the run.

Initial policy target:

[source,text]
----
MemoryMax       768 MiB
MemorySwapMax   0 (or equal to MemoryMax if runner policy requires it)
TasksMax        64
CPUQuota        100%
wall timeout    20 s default
/tmp            128 MiB
/home           16 MiB
/work           64 MiB
----

The exact values are policy/versioned data, not hard-coded security conclusions.
Known-good plugin corpus measurements should drive later tuning.

== Seccomp

Pass 2 introduces a versioned seccomp policy in addition to namespaces.
`tools/build-rift-seccomp.sh` compiles a libseccomp-generated BPF program and
`exec-bwrap-seccomp.sh` hands it to Bubblewrap by inherited file descriptor, so
the policy is applied to the prisoner only after Bubblewrap has constructed the
namespaces. Production execution requires a non-empty policy file.

Candidate deny set for empirical validation:

[source,text]
----
kexec_load / kexec_file_load
reboot
init_module / finit_module / delete_module
swapon / swapoff
mount / umount2 / pivot_root
keyctl / add_key / request_key
bpf
perf_event_open
ptrace (except if a future observer explicitly requires a constrained form)
setns
unshare
process_vm_readv / process_vm_writev
open_by_handle_at / name_to_handle_at
new mount API calls (fsopen/fsconfig/fsmount/fspick/open_tree/move_mount)
AF_PACKET and raw sockets
----

`clone`/`clone3` are intentionally not blanket-denied because the .NET runtime
needs normal thread creation. Namespace creation is denied with `unshare` and
`setns` after the jail already exists. The policy remains corpus-tunable and
must gain syscall-observation regression coverage before Phase 5.

== Dynamic loader and Dalamud compatibility repair

The uploaded prototype mixes two lifecycle generations and cannot currently be
used as proof that a wild API-15 plugin executes correctly.

Known repairs:

. Use one shared `Dalamud` contract identity between the host and plugin load
  context. Do not load a second incompatible copy that makes otherwise-identical
  interface types fail assignability checks.
. API-15 `IDalamudPlugin` is lifecycle-marker + `IDisposable`; constructor and
  Dalamud service injection happen before normal operation. Do not search for an
  `Initialize(IDalamudPluginInterface)` method that no longer exists.
. API-15 `IAsyncDalamudPlugin` uses `LoadAsync(CancellationToken)` and
  `IAsyncDisposable.DisposeAsync()`.
. Implement `[PluginService]` injection before constructor execution where the
  plugin uses static service properties, then support resolvable constructor
  injection and instance injection.
. Model `IDalamudPluginInterface` as the real API-15 contract (or a generated
  instrumented implementation/proxy), not the old three-member interface.
. Add services Omega itself needs as mandatory coverage fixtures:
  `ICommandManager`, `IPluginLog`, `ITextureProvider`, `IDalamudAssetManager`,
  `ITitleScreenMenu`, `IGameInteropProvider`, and `INotificationManager`.
. Dependency resolution must be artifact-local and deterministic. It must never
  probe the runner home, global NuGet caches or arbitrary host paths.
. Every missing service/member becomes a coverage observation; it must not be
  silently converted into a security finding.

Pseudo-sequence:

[source,csharp]
----
var artifact = VerifyAndHashArtifact(input);
using var loadContext = CreateRestrictedPluginLoadContext(artifact.Directory);
var pluginType = LocatePluginType(loadContext, artifact.EntryAssembly);

InjectStaticPluginServices(pluginType, serviceRegistry);
var plugin = ConstructWithResolvableServices(pluginType, serviceRegistry);
InjectInstancePluginServices(plugin, serviceRegistry);

if (plugin is IAsyncDalamudPlugin asyncPlugin)
    await asyncPlugin.LoadAsync(cancellationToken);

RunScenarioTicks(serviceRegistry.Framework, scenario);

if (plugin is IAsyncDisposable asyncDisposable)
    await asyncDisposable.DisposeAsync();
else if (plugin is IDisposable disposable)
    disposable.Dispose();
----

The external Bubblewrap supervisor remains authoritative even after cancellation
is added to the host.

== Observation model

Rift should stop acting like a second static security scanner. Static URL,
metadata and reachability analysis belong to SigmaScope. Rift's enduring output
is runtime observation.

Target observation classes:

[source,json]
----
{
  "schema": "omega.rift-observation.v1",
  "producer": "interdimensional-rift",
  "artifact": {
    "sha256": "...",
    "entry_sha256": "...",
    "internal_name": "..."
  },
  "environment": {
    "executor": "bubblewrap",
    "executor_version": "...",
    "image_or_runtime_digest": "...",
    "dalamud_api": 15,
    "shim_revision": "...",
    "scenario_revision": "...",
    "network": "isolated"
  },
  "scenario": "constructed_logged_out",
  "phase": "constructor",
  "operation": "service.touch",
  "subject": "Dalamud.Plugin.Services.ICommandManager",
  "member": "AddHandler",
  "parameters": {
    "command": "/omega"
  },
  "outcome": "simulated"
}
----

Rift observations do not carry `low`, `medium`, `high` or `critical` merely
because an operation occurred. Correlation is separate.

Examples:

[source,text]
----
SigmaScope: process execution capability statically reachable
Rift:       process execution attempted during constructor
SRL:        correlate the two observations into a stronger fact/finding

SigmaScope: endpoint literal api.example.com
Rift:       DNS/connect attempt observed for api.example.com
SRL:        correlate endpoint identity + observed runtime use
----

"Not observed" MUST never be projected as "cannot do this". A report records the
scenarios and coverage that actually ran.

== Scenario model

Phase 3 introduces deterministic scenarios rather than several identical empty
framework ticks.

Initial scenarios:

* `constructed_logged_out`
* `logged_in_idle`
* `ui_ready`
* `framework_ticks`
* `dispose`

Later scenarios may include territory change, condition transition, command
registration/use, UI draw callback, IPC provider/subscriber interaction and
addon lifecycle events. Scenarios must be deterministic and versioned.

Each report records:

[source,text]
----
scenario id + revision
start/end outcome
members simulated
members unavailable
callbacks triggered
callbacks skipped
coverage truncation / timeout
----

== OS-level observation

Dalamud service instrumentation sees only calls that pass through the simulated
Dalamud API. A hostile plugin can bypass it with BCL/native APIs.

Phase 4 therefore adds OS-level observation around the sandbox. Candidate
sources include seccomp user notifications/audit-style capture, eBPF from a
trusted outer observer, or a tightly controlled network sink. The observer MUST
live outside the untrusted plugin process.

Interesting operation families:

[source,text]
----
connect / socket / DNS intent
openat / create / write / rename / unlink
execve / execveat
native library mapping/loading
mprotect executable mappings
clone/thread/process creation
attempted namespace operations
----

The first network implementation remains `--unshare-net` with no route. A later
controlled network namespace may provide fake DNS/TCP/HTTP sinks to capture
intended destinations without allowing Internet egress.

== CI trust separation

Rift execution belongs in an untrusted job. Catalog publication belongs in a
later trusted job.

[source,text]
----
trusted fetch/stage job
    |
    | artifact + expected SHA only
    v
Rift job (no write token, no secrets, no network)
    |
    | raw observation artifact
    v
trusted ingestion job
    |
    | validate schema, artifact hash, producer/environment provenance
    v
SigmaScope/SRL evidence store
----

The Rift job MUST NOT possess credentials that can publish catalog data. A full
compromise of the plugin/Rift process must therefore be unable to directly alter
Omega's trusted catalog.

== Test plan and acceptance gates

=== Boundary tests

* Bubblewrap executable exists and is neither setuid nor file-capability enabled.
* required user/PID/IPC/network/UTS namespaces are successfully created;
* host environment sentinel is absent inside the jail;
* no default network route exists;
* nested user namespace creation fails;
* plugin input is read-only;
* runner home/workspace are absent;
* outer timeout kills a deliberately hanging child/process tree;
* bounded tmpfs cannot grow beyond policy;
* production runner refuses to execute if any mandatory probe fails.

=== Host/API tests

The old smoke test MUST NOT accept `not_a_plugin`, `load_failed` or
`init_timeout` as success for the positive fixture.

Required fixtures:

. synchronous API-15 constructor/plugin-service fixture;
. asynchronous `LoadAsync` fixture;
. constructor injection fixture;
. service-touch fixture;
. dependency-resolution fixture;
. deliberate init exception fixture;
. deliberate dispose exception fixture;
. deliberate hang + child process fixture;
. Omega Client compiled plugin as a mandatory real-world positive fixture.

The Omega fixture passes only when Rift gets far enough to record expected Omega
service registration/touches. Merely reading static strings is not a pass.

=== Security regression corpus

Known-good plugins establish compatibility/noise baselines. Deliberately hostile
fixtures verify blocking/observation of network, files, process execution,
reflection/native load and exhaustion attempts.

the checked-in generated surface was repaired from the frozen surface manifest
so known cases such as `CommandInfo.set_HelpMessage` exist immediately. Frozen
Dalamud dependency references are copied into runtime publications rather than
probing arbitrary host paths at execution time.

The positive test contract is intentionally stricter: `not_a_plugin`,
`load_failed` and `init_timeout` cannot satisfy the synchronous fixture. An
async fixture verifies `LoadAsync`/`DisposeAsync`. `RIFT_OMEGA_FIXTURE` can point
to a compiled Omega DLL; the gate requires all eight current Omega services to

Validation possible in this environment is source/static only: shell syntax and
the API-15 source-contract gate pass. A live Bubblewrap/cgroup/seccomp run and
C# build still require the GitHub `ubuntu-24.04` workflow or a machine with the
pinned Dalamud API-15 Hooks dependency set and .NET 10 SDK.

== Git/ZIP script-mode portability

The GitHub-hosted executor MUST NOT depend on the executable bit surviving a ZIP extraction or a Windows checkout.
Rift's workflow invokes trusted shell helpers explicitly through `/bin/bash`, and the outer supervisor invokes its helper scripts through `/bin/bash` as well.
This is intentional: a source import that records `tools/*.sh` as Git mode `100644` must not disable the security boundary.

A `.gitattributes` file pins shell/workflow/source text to stable line endings so a Windows checkout cannot introduce CRLF interpreter failures.
Executable mode `100755` remains desirable for normal Linux ergonomics, but it is no longer a correctness or security dependency.


== Pass 2.2: Dalamud-style published-package self scan

Rift now has a CI workflow that acquires Omega the way Dalamud would: it reads the stable PluginMaster, follows the immutable versioned DownloadLinkInstall, verifies the published SHA-256 sidecar, then passes the opaque package to a separate hostile-execution job.

The hostile job extracts the exact package with ZIP safety checks, verifies DalagabOmega.json against the feed version, and executes DalagabOmega.dll only inside the cgroup-v2 -> Bubblewrap -> seccomp boundary. Results are always preserved as the `rift-omega-results` Actions artifact before a non-zero Rift execution status fails the job.

== Alpha reference subject (original canary-fixture lineage)

Rift includes a deliberately suspicious regression fixture under `tests/fixtures/RiftAlpha`.
It exists to light up SigmaScope/YARA static rules and Rift runtime observation paths without performing malicious actions.

The fixture has a strict non-distribution contract:

* the executable artifact contains exactly `RiftAlpha.dll`;
* it contains zero JSON files and therefore no Dalamud plugin manifest/feed document;
* its source contains none of the normal Dalamud feed/manifest keys;
* outside `RIFT_EXECUTOR=bubblewrap-v2` it is inert;
* active probes target only Rift tmpfs, isolated loopback, deliberately missing executables/libraries/assemblies, a read-only non-existent registry key, and `libc.getpid()`;
* credential theft, process injection, persistence, security tampering, AMSI patching and anti-analysis behavior are represented only as static marker vocabulary and are never invoked.

`tools/check-alpha-contract.py` fails closed if those invariants drift. `.github/workflows/rift-alpha.yml` builds a DLL-only opaque fixture artifact, asserts it contains no JSON, executes it through cgroup-v2 -> Bubblewrap -> seccomp, verifies Alpha runtime observations and preserves the resulting report.


== Pass 2.4: real Dalamud contract assembly

The generated full-surface C# shim is retired from the active execution path. CI demonstrated that reflection metadata cannot be naively round-tripped into legal C# for static classes, ref structs, default interface members, abstract overrides, pointer signatures, and complex BCL contracts.

Rift now loads the frozen trusted real `Dalamud.dll` only as a contract/type-identity assembly. It never instantiates Dalamud host/game services. Plugin-facing services remain Rift `DispatchProxy` instrumentation objects created against the real service interface `Type` objects. The trusted contract directory is mounted read-only at `/contracts` inside Bubblewrap.

DalaInspect remains metadata/provenance tooling and runs with `--inspect-only`; generated C# is no longer a prerequisite for building or running Rift.


== Pass 2.5: CI integration repair

The `ec68b40` GitHub runs reconfirmed that user namespaces, Bubblewrap, cgroup-v2 and the seccomp policy all work on hosted Ubuntu 24.04 runners. The remaining failures were pre-execution integration defects: two fixture projects had not received the real-Dalamud contract import in the committed branch, the Alpha source checker treated NuGet-generated `obj/*.json` as authored plugin metadata, and the Omega job summary assumed a runtime report existed after a pre-build failure.

Pass 2.5 restores all contract imports, keeps the final Alpha package hard-gated to one DLL and zero JSON, ignores only generated `bin/obj` files in the authored-source check, and makes both execution workflows preserve phase-specific diagnostics for early failures.


== Pass 2.8: Dalamud internal-service fail-fast mode

Rift uses the real frozen `Dalamud.dll` only as a trusted CLR contract/type-identity source.
Some plugins nevertheless reflect into unsupported Dalamud internals such as
`Dalamud.Service<T>.Get()`. In a normal client those calls are satisfied by Dalamud's
`ServiceManager`; in Rift the real host is intentionally never started.

Current Dalamud's `Service<T>.Get()` waits on an internal `TaskCompletionSource<T>` and
uses `ServiceManager.UnloadCancellationToken` to abort that wait during host unload.
Rift now deliberately cancels the corresponding trusted runtime unload token before
plugin execution. This makes unsupported internal service-locator calls fail immediately,
allowing well-defended plugin reflection bridges to take their own fallback paths rather
than deadlocking the sandbox.

This does not make real Dalamud internal services available and does not instantiate
game/host internals. Plugin-facing public services remain Rift instrumentation proxies.


== Phase 3: runtime-observation contract

Rift's active report schema is now `rift.runtime-observation.v2`.
The previous `FindingSeverity`, static `Capability` findings, and `HttpReferenceScanner`
are removed from the runtime path. Static capability and specialist signature analysis
belong to SigmaScope/YARA/etc. Rift emits neutral evidence only: lifecycle, service
injection/access, logs, assembly loading, exceptions/timeouts, and explicit boundary
mode observations.

The absence of a runtime observation means only "not observed in this scenario".
It must never be interpreted as proof that the artifact lacks the corresponding capability.

A new DLL-only `RiftCanary` provides finite boundary probes. It is inert outside
`RIFT_EXECUTOR=bubblewrap-v2` and contains no plugin manifest JSON. The dedicated workflow
asserts that the exact staged artifact is read-only, GitHub runner credentials/workspace
are absent, nested user namespaces are denied, and AF_PACKET raw sockets are denied.


== Pass 3.1: canonical Alpha/Canary naming and containment qualification

The active terminology is now:

* Rift = sandbox;
* Alpha = known suspicious-looking, harmless observation-calibration subject;
* Canary = environmental boundary sentinel.

The old `RiftHostileCanary` and `RiftBoundaryCanary` source/workflow identities are retired from the active tree.

Canary now checks read-only `/input`, `/rift`, and `/contracts`; secret/workspace absence; no-new-privileges; zero effective capabilities; network-route isolation; nested-userns denial; ptrace denial; raw-packet denial; bounded tmpfs mounts; and the isolated hostname.

Four additional non-distributable stress fixtures qualify cgroup/tmpfs/process-tree containment:

* `RiftMemoryPressure`;
* `RiftTaskPressure`;
* `RiftTmpfsPressure`;
* `RiftHangTree`.

`RiftHangTree` includes a tiny test helper that intentionally ignores SIGTERM. The outer service remains configured with `KillMode=control-group`, `TimeoutStopSec=2s`, and `SendSIGKILL=yes`; the workflow verifies no helper process survives teardown.

The managed producer version advances to `0.3.0`. `rift.supervisor.v3` classifies pre-report process kills and records the same boundary profile information needed to interpret destructive qualification runs.
