# Local Investigator notebooks and cases

DeltaScope Investigator cases are a **local research notebook**, not part of Omega's security authority chain. They help an investigator keep context while moving between plugins, findings, retained observations, intelligence relationships and historical Evidence-v2 snapshots.

## What a case can contain

A local case can store:

- a title, summary, status and local labels;
- free-form investigator notes;
- plugin bookmarks;
- pinned finding references;
- pinned retained-observation references;
- saved threat-intelligence / relationship pivots;
- references to the Evidence-v2 snapshot and revisions that were being inspected.

Pins are references, not copies of authoritative findings. Snapshot references retain useful identity such as plugin/variant, scan, Evidence/Definitions/rule-set revision and artifact hash when those fields are available, so later Evidence refreshes do not erase the investigator's original context.


## Reference health and timeline

When a case is opened, DeltaScope resolves pinned references against the currently verified evidence view. The case remains local; the resolver is only an explanation layer. Pins can be shown as:

- **Current** — the exact pinned scan/artifact identity is still current;
- **Retained** — the exact old scan/artifact is no longer current but is still present in retained Evidence-v2 history;
- **Re-observed** — the original finding was pinned on an older scan and a matching finding is observed again on the current scan;
- **Changed** — the plugin still exists but the exact pinned evidence no longer resolves;
- **Unresolved / missing** — DeltaScope cannot prove the referenced relationship/object still exists.

The resolver never upgrades an approximate match into an exact historical claim. If the old scan cannot be proven, DeltaScope says so instead of silently redirecting the pin to current evidence. Resolution is bounded to the first 250 pins per refresh and reuses one plugin dossier fetch for multiple pins on the same variant.

The **Timeline** combines local case creation, notes and pin times with any retained `scannedAtUtc` timestamps captured by the pin. It is an investigator chronology, not a security-event authority or runtime execution claim.

## Storage

By default DeltaScope writes cases below:

```text
~/.omega/deltascope/investigator/v1/
```

The location can be overridden with `OMEGA_DELTASCOPE_CASE_HOME` or `--case-home`. Each case is a bounded JSON document written atomically by DeltaScope. Case IDs and item IDs are generated by DeltaScope; arbitrary filenames are never accepted. The store rejects a symlinked case root and enforces limits on case count, notes, pinned items and file size.

## Authority boundary

Local casework deliberately declares all of the following as false:

- `securityAuthority`
- `findingAuthority`
- `policyInput`
- `productionWriteBack`
- `evidenceWriteBack`
- `definitionsWriteBack`
- `queueMutationAuthorized`
- `publicationWriteBack`
- `repositoryWriteBack`

`localOnly` is true. Nothing in a case can raise/lower severity, create/close a production finding, change Stigma-1 activation, enqueue a scan, modify Definitions, modify Evidence-v2, publish data, or write back to the repository.

The intended flow is therefore:

```text
Published Evidence-v2 / Definitions
             |
             v
        DeltaScope
             |
             +---- read / pivot / compare
             |
             +---- local Investigator case
                        |
                        +---- notes
                        +---- bookmarks
                        +---- pinned references
                        +---- saved pivots

No arrow returns from the case to security authority.
```

If research from a case should become a new security rule or product change, that transition happens through the normal reviewed development path. The case itself never becomes production input.

## Using cases in DeltaScope

Switch to the **Investigator** perspective and open **Cases**. Create or select a local case, then make it the active case. While investigating, supported findings, observations, threat-intelligence pivots and plugin dossiers expose **Pin to case** actions. Pinned items can be reopened later when the referenced published object is still available.

DeltaScope persists the active case choice in browser-local UI state. The case content itself is kept on the local filesystem, so restarting the browser does not discard it.
