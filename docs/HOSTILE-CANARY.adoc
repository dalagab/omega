= Interdimensional Rift Hostile Behavior Canary
:toc:

== Purpose

`RiftHostileCanary.dll` is a deliberately suspicious security regression fixture. It exists to prove that SigmaScope static analysis, reviewed YARA rules, and Interdimensional Rift dynamic observation continue to detect high-risk behavior patterns without shipping or executing malicious behavior.

It is a test artifact, not a plugin for users.

== Non-distribution contract

The canary is intentionally unusable as a normal Dalamud package.

* The CI-produced fixture archive contains exactly one file: `RiftHostileCanary.dll`.
* The fixture archive contains zero `.json` files.
* There is no Dalamud manifest, repository entry, PluginMaster entry, download URL, API-level declaration, or normal plugin metadata document.
* The canary source lives under `tests/fixtures/`, not a distributable plugin/repository tree.
* `tools/check-hostile-canary-contract.py` fails if normal Dalamud manifest/feed keys are introduced.
* The active runtime probes are inert unless `RIFT_EXECUTOR=bubblewrap-v2` is present.

This is stronger than making a malformed Dalamud JSON document: there is no plugin JSON for Dalamud or a JSON-based plugin scraper to consume.

== Safety model

The canary has two classes of indicators.

=== Static-only hostile vocabulary

The following behaviors are represented only by strings/metadata. They are never executed:

* browser credential/DPAPI collection plus webhook exfiltration;
* Discord LevelDB token collection plus exfiltration;
* Windows Credential API plus exfiltration;
* classic `OpenProcess` / `VirtualAllocEx` / `WriteProcessMemory` / `CreateRemoteThread` injection;
* `NtCreateThreadEx` injection;
* encoded PowerShell download/execute;
* Defender exclusion/realtime-protection tampering;
* base64 PE decoding/dynamic loading;
* AMSI memory patch markers;
* Run/RunOnce persistence;
* scheduled-task persistence;
* service persistence;
* anti-debug API cluster;
* anti-VM environment cluster.

These markers intentionally cover the current 14 Omega Core reviewed YARA rules.

They also include the current SigmaScope static primitive vocabulary for HTTP, sockets, process launch, shell/PowerShell, and credential APIs. The expected SRL correlations therefore include network + execution and credential + network when the canary is scanned by a compatible SigmaScope build.

=== Harmless runtime probes

When and only when executed by `bubblewrap-v2`, the canary performs bounded sentinel operations:

[cols="1,2,2"]
|===
|Probe |Target |Safety property

|Filesystem write
|`/tmp/rift-hostile-canary/sentinel.txt`
|Rift tmpfs only; file and directory are deleted immediately.

|TCP
|`127.0.0.1:9`
|Loopback inside Rift's isolated network namespace; no Internet/LAN route.

|HTTP
|`http://127.0.0.1:9/rift-canary`
|Same isolated loopback target with a 250 ms timeout.

|Process launch
|`/rift/RIFT_CANARY_DOES_NOT_EXIST`
|Deliberately absent path; no hostile executable exists to launch.

|Managed dynamic load
|`RiftHostileCanary.Does.Not.Exist`
|Deliberately missing assembly.

|Native dynamic load
|`rift_hostile_canary_does_not_exist.so`
|Deliberately missing library.

|Registry
|`Software\RiftHostileCanary\Sentinel`
|Read-only, non-existent key; no creation/write.

|P/Invoke
|`libc.getpid()`
|Harmless process-ID query.
|===

== Expected SigmaScope static alarms

For a compatible SigmaScope 2.15 scan of the compiled canary DLL, the fixture is designed to produce at least these primitive facts:

* `network.http`
* `network.socket`
* `process.launch`
* `shell.powershell`
* `credential.api`

and these correlations:

* `compound.network-execute`
* `compound.credential-network`

The reviewed Omega Core YARA corpus is intentionally expected to match all 14 current first-party compound/anomaly rules. A future rule change may intentionally alter this list; such a change must update the canary contract in review rather than silently weakening the fixture.

== Expected Rift runtime observations

The dynamic report must contain markers for:

* canary armed inside Rift;
* temporary-filesystem probe;
* loopback TCP probe;
* loopback HTTP probe;
* missing-process probe;
* missing-assembly probe;
* missing-native-library probe;
* read-only registry probe;
* harmless P/Invoke probe;
* framework tick;
* normal disposal.

Outside Rift the canary must log that it is inert and must not emit the active probe markers.

== Publication rule

Do not add this fixture to Omega's repository feed, PluginMaster, release package, catalog source registry, or public plugin discovery surface. It exists only in the Rift/security test tree and as short-lived CI artifacts.
